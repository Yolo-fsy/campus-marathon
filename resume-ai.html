面向个人文档的检索增强问答应用：上传 txt / md / pdf 后自动切片入库，提问时先检索最相关片段，再交给大模型生成带引用的回答，全程流式呈现。已作为独立模块集成进 Java Web 项目并部署验证。

  • RAG 检索链路：PDFBox 解析 PDF、按 UTF-8 读取 txt / md，统一做空白归一化；按 500 字窗口 + 100 字重叠切片并优先在段落 / 句号边界断开；查询侧用中文 bigram 分词 + BM25（k1=1.5、b=0.75）排序取 Top-4 片段，拼入提示词并编号，回答末尾展示引用文档、段号与相关度。
  • 模型接入与流式输出：基于 JDK HttpClient 调用 OpenAI 兼容的 /chat/completions（stream=true），逐行解析 SSE 增量并转发给前端；自实现 JSON 转义与 delta 内容解析，兼容空 delta、null content 与 [DONE] 结束标记；异常统一以 event: error 返回，聊天页不中断。
  • 可用性与降级：模型地址、模型名与密钥全部外置到配置文件，并支持环境变量 AI_API_KEY 覆盖，避免密钥入库；未配置密钥时自动进入检索演示模式，直接回显相关片段并提示配置方式，保证无 Key 也能走通上传 → 检索 → 展示全流程。
  • 数据与权限：设计 kb_document / kb_chunk 两张表，文档与切片分级存储；上传、列表、删除、问答四类接口均按登录用户隔离，参赛者只能操作本人文档，管理员可查看全部；上传限制 5MB，服务端二次校验文件类型与大小。
  • 前端交互：实现文档库卡片列表与聊天页，支持拖拽 / 点击上传、检索范围切换（全部文档或指定文档）；用 fetch 读取 SSE 流，按事件类型分别渲染 token、引用卡片与错误提示，自动滚动并禁用重复提交。

  • 多维度评分与权重校验：管理员为每场竞赛配置评分维度（如技术难度 / 创新性 / 完成度，权重 0–100），保存时校验权重和必须等于 100；竞赛进入评审阶段后锁定维度，防止评分过程中再改权重导致分数失效。

自我评价
